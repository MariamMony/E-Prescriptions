# نظام إدارة الصيدليات والوصفات الطبية (e_prescriptions)

نظام سطح مكتب متكامل واحترافي لإدارة الصيدليات ونقاط البيع الطبية (POS)، مصمم ومبني من الصفر ليعمل **محلياً بالكامل بدون الحاجة لأي اتصال بالإنترنت (100% Offline)**، مع واجهة مستخدم عربية كاملة من اليمين إلى اليسار (RTL).

**المطور:** ماجد القبانى  
**العملة الرسمية:** الجنيه المصري (ج.م / EGP)

---

## 2. التوافقية الصارمة مع Windows 7 SP1 فما فوق (Compatibility)

- **أنظمة التشغيل المدعومة:**
  - Windows 7 Service Pack 1 (32-bit & 64-bit)
  - Windows 8 / 8.1 (32-bit & 64-bit)
  - Windows 10 (32-bit & 64-bit)
  - Windows 11 (64-bit)
- **المنصة والترجمة:** `AnyCPU` مع ضبط `<Prefer32Bit>false</Prefer32Bit>` بحيث يعمل نفس الملف التنفيذي على أنظمة 32 بت و 64 بت بكفاءة أصلية تامة.
- **الخطوط:** تم اعتماد تسلسل خطوط آمن ومتوفر في كافة نسخ ويندوز: `Segoe UI, Tahoma, Arial` معرف مركزياً في `Resources/Fonts.xaml`.
- **الأيقونات المتجهة:** تم تجنب خط `Segoe MDL2 Assets` (لأنه غير موجود في Windows 7)، واستبداله بأيقونات فيكتور مرسومة يدوياً كـ `Geometry (Path Data)` داخل `Resources/Icons.xaml`.
- **بدون بطاقة شاشة قوية:** تجنب مؤثرات `DropShadowEffect` و `BlurEffect` الثقيلة، والاعتماد على حدود خفيفة وتدرجات لونية سلسة تعمل بسلاسة تامة على الأجهزة الاقتصادية وأجهزة الكاشير القديمة (POS Terminals) وشاشات 1366×768.

## 3. التعامل مع ملفات SQLite الأصلية (x86 & x64 Native Interop)

عند بناء المشروع بنمط `AnyCPU`، يحتاج محرك SQLite إلى مكتبة C++ الأصلية `SQLite.Interop.dll`.  
حزمة `Stub.System.Data.SQLite.Core.NetFramework` تتكفل بنسخ هذه الملفات أثناء البناء داخل مجلدي إخراج فرعيين:
```
ePrescriptions.App\bin\Release\net48\
├── ePrescriptions.exe
├── ePrescriptions.exe.config
├── System.Data.SQLite.dll
├── CommunityToolkit.Mvvm.dll
├── ClosedXML.dll
├── x86\
│   └── SQLite.Interop.dll   <-- لبيئات 32 بت
└── x64\
    └── SQLite.Interop.dll   <-- لبيئات 64 بت
```
يقوم محرك SQLite عند الإقلاع باكتشاف معمارية نظام التشغيل (32 بت أو 64 بت) وتحميل الملف المناسب تلقائياً بدون أي تدخل يدوي، مما يمنع حدوث خطأ `BadImageFormatException` أو `DllNotFoundException`.

## 4. البنية المعمارية للحل (Clean Architecture Solution)

يتكون الحل من 5 مشاريع مفصولة المسؤوليات بصيغة SDK-Style csproj على .NET Framework 4.8 و C# 9.0:

```
e_prescriptions/
├── src/
│   ├── ePrescriptions.Core/         # أدوات المال (Money)، التاريخ (DateHelper)، الأمان (PBKDF2)، الطباعة، والمسجلات
│   ├── ePrescriptions.Domain/       # الكيانات (Entities)، التعدادات (Enums)، ونماذج التقارير
│   ├── ePrescriptions.Data/         # محرك SQLite، ترقيات الجداول (Migrations)، ومستودعات البيانات (Repositories)
│   └── ePrescriptions.App/          # تطبيق WPF (Views, ViewModels, XAML Styles, Navigation, DI)
├── tests/
│   └── ePrescriptions.Tests/        # اختبارات الوحدات لضمان دقة الحسابات، التجزئة، الهجرة، والنسخ الاحتياطي
├── installer/
│   └── e_prescriptions_installer.iss # سكريبت Inno Setup لإنتاج مثبت تنفيذي .exe رسمي
├── build.bat                        # سكريبت أتمتة البناء والتحزيم لـ Windows
├── publish.ps1                      # سكريبت PowerShell للنشر السريع
└── e_prescriptions.sln              # ملف الحل البرمجي لـ Visual Studio
```

## 5. قواعد الأمان وقاعدة البيانات

1. **مسار قاعدة البيانات:**
   يتم إنشاء وحفظ قاعدة البيانات في مجلد البيانات المشترك لكل مستخدمي الجهاز:
   `%ProgramData%\ePrescriptions\e_prescriptions.db` (ومعها `backups` و`logs` و`exports`)
   ولا تُحفظ أبداً في مجلد البرنامج لضمان عدم وجود مشاكل في صلاحيات الكتابة (UAC).
   التثبيتات القديمة (`%AppData%\e_prescriptions`) تُنسخ تلقائياً عند أول تشغيل بعد التحديث (النسخة القديمة لا تُحذف).
2. **وضع WAL والمعاملات الذرية:**
   يتم تفعيل `PRAGMA journal_mode = WAL;` و `PRAGMA foreign_keys = ON;`، ويتم تنفيذ عمليات الفاتورة (حفظ الفاتورة + حفظ البنود + خصم المخزون بنظام FEFO + قيد اليومية + تحديث رصيد العميل أو الصندوق) داخل Transaction ذرية واحدة محكمة لمنع تلف البيانات عند انقطاع الكهرباء.
3. **دقة الحسابات المالية (Money Struct):**
   جميع القيم المالية (أسعار، مبيعات، تكلفة، ضرائب، قروض، زكاة) تُخزن كأعداد صحيحة (`long`) تمثل القروش (1 جنيه = 100 قرش)، مع تطبيق تقريب النصف للأعلى (AwayFromZero / Half-Up) لمنع أي أخطاء حسابية ناتجة عن الفواصل العائمة.
4. **قفل النسخة الواحدة (SingleInstanceMutex):**
   قفل البرنامج بـ `Mutex` مخصص لمنع تشغيل نافذتين في آن واحد وتجنب تعارض الملفات.

## 6. خطوات البناء والتشغيل (Build & Run)

### المتطلبات المسبقة:
- Visual Studio 2022 (أو 2019) مع تثبيت حزمة **.NET desktop development** ومكون **.NET Framework 4.8 targeting pack**.
- برنامج Inno Setup 6 (اختياري لبناء ملف التثبيت .exe).

### البناء السريع عبر سكريبت الأتمتة:
قم بتشغيل الملف التالي من سطر الأوامر:
```cmd
build.bat
```
سيقوم السكريبت تلقائياً بـ:
1. استعادة كافة حزم NuGet بدقة.
2. بناء كافة المشاريع بنمط `Release AnyCPU`.
3. تنفيذ الاختبارات الآلية للتأكد من خلو النظام من أي أخطاء.
4. التحقق من نسخ ملفات `SQLite.Interop.dll` في مساري `x86` و `x64`.
5. تجميع ملف التثبيت `e_prescriptions_Setup_v1.0.0.exe` داخل مجلد `dist\installer\`.
